OrientationHow to use this guide

This document is a learning companion, not a substitute for practice. Each problem is presented in the same sequence: the task and its constraints, the central idea, a visual design blueprint, a worked trace, a correctness argument, an analysis of complexity and pitfalls, and finally a complete reference implementation.

Recommended study cycle

  1. Read the statement only. Cover the solution section and restate the problem in your own words. Identify the input, the output, and the exact formatting rules.
  2. Attempt a solution for 45–90 minutes. Draw the data structure on paper before writing code. Compile early and often with warnings enabled.
  3. Compare designs, not just answers. Read the design blueprint and correctness argument. If your approach differs, ask whether it is also correct and what it costs in time and memory.
  4. Run the tests. Use the supplied suite, then add at least one boundary case of your own. A program that passes the samples is not yet a verified program.
  5. Reflect in writing. Record the bug you found, why it happened, and the smallest input that exposed it. This is how debugging skill becomes transferable.

Prerequisites

What you should already know

Variables and arithmetic, if/for/while, functions, one- and two-dimensional arrays, strings, and basic pointer syntax. Familiarity with scanf, printf, and fgets is assumed.

Learning outcomes

What you will practise

Translating a specification into invariants; choosing between simulation and mathematical reduction; using a stack and a queue; reasoning about boundaries; proving termination and correctness; and testing exact textual output.

Assessment

How to judge your own work

A solution is complete when it compiles without warnings, passes every supplied test, survives additional edge cases, and you can explain the correctness argument aloud without reading the code.

Integrity

Use the reference responsibly

Attempt the problem first. When you consult a listing, close it and rewrite the solution from memory. Cite any code you adapt, and never submit work you cannot explain or modify under exam conditions.

Core conceptsFoundations and working habits

The five problems look different, but they rest on a small set of shared ideas. Understanding these ideas explicitly makes each new problem feel like a variation on familiar ground rather than an isolated trick.

Concept 01

Exact input and output

Competitive and assessment programs are usually compared byte for byte. A trailing space, a missing newline, a stray prompt, or the wrong zero padding is a failure even when the mathematics is correct. Read the output specification as carefully as the algorithm.

Concept 02

Arrays and row-major storage

A two-dimensional array a[N][M] is stored row by row. The valid indices are 0 <= i < N and 0 <= j < M. Most boundary bugs come from confusing the two dimensions or from using a one-based formula on a zero-based array.

Concept 03

Stacks: last in, first out

A stack supports push and pop at one end. It is the natural model for nested obligations: the most recently opened bracket must be the next one closed. An array plus an integer top is sufficient.

Concept 04

Queues and breadth-first search

A queue is first in, first out. Breadth-first search uses a queue to visit all nodes at distance d before any node at distance d+1. The queue therefore encodes the level structure of a graph or tree.

Concept 05

Loop invariants and induction

An invariant is a statement that is true before and after every iteration. If it holds initially, is preserved by the loop body, and implies the goal when the loop ends, the algorithm is correct. The Josephus recurrence is proved by mathematical induction instead.

Concept 06

Complexity and resource bounds

State both time and memory. A solution that is fast enough for N <= 100 may be unusable for N = 10^6. The constraints are part of the problem statement, not decoration.

Why output formatting deserves its own habit

The banded-matrix and spiral problems are especially strict. The banded problem requires printf("%04d", value), whose field width includes the sign: -5 becomes -005 and -24 becomes -024. The spiral problem requires exactly one space between values and no space after the last value. A useful habit is to make the separator conditional on position, as in if (i > 0) putchar(' ');, rather than printing a space after every element and trying to remove the last one later.

Design blueprint · a repeatable workflow

  1. Model the data. What are the objects, their dimensions, and their valid ranges? Write these down before choosing a structure.
  2. State the invariant. What remains true at the start of every loop iteration? For a stack, it is the set of unmatched openers; for spiral traversal, it is the unvisited rectangle.
  3. Handle degeneracy. Ask what happens when a dimension is one, when a graph has one node, or when a band has zero width.
  4. Separate computation from presentation. Compute the answer in ordinary variables, then format it in one final pass.
  5. Verify by trace. Execute the algorithm by hand on the smallest interesting input and on the sample inputs.

Habit to avoid

Do not debug by adding printf statements to a program whose output is itself being compared. Diagnostic text will be treated as part of the answer. Send diagnostics to stderr (fprintf(stderr, ...)) and remove them before submission, or use a debugger. Similarly, never submit a program that prints prompts such as Enter N:.

Problem 01 · Structured sparsityGeneral Banded Matrix Multiplication

Multiply two square matrices that are mostly zero, and exploit the known shape of the zeros instead of paying for a full cubic product.

Input
N p q r s, then two N × N matrices
Output
Product, printed with %04d
Core idea
Intersect the two band ranges for each output cell
Cost
O(N³) worst case, O(N²) memory

Statement

Given two N × N matrices A and B, compute C = A × B. Both matrices are banded: entries outside a limited band around the main diagonal are zero. Using zero-based indices,

  • A[i][j] = 0 whenever i - j > p or j - i > q; equivalently, i - p <= j <= i + q.
  • B[i][j] = 0 whenever i - j > r or j - i > s; equivalently, i - r <= j <= i + s.

The product is defined by the usual formula

Cij = ∑k Aik Bkj   for   0 ≤ k ≤ N − 1.

Because of the bands, only a contiguous range of k can contribute:

max(0, i − p, j − s)  ≤  k  ≤  min(N − 1, i + q, j + r).

If the lower bound exceeds the upper bound, C[i][j] = 0. The input satisfies 1 <= N <= 20, 0 <= p, q, r, s < N, and every matrix entry is between -99 and 99.

Output specification

Print exactly N lines of N integers. Each integer is printed with printf("%04d", value): at least four characters, padded with leading zeros, with the minus sign counted as one character. Consecutive values in a line are separated by one space, with no trailing space. Print no headings, labels, or prompts.

Concept · sparsity is structure, not absence

A zero entry is information. If a matrix is known to be zero outside a band, then every product that would use an outside entry is known to be zero before any arithmetic happens. The algorithmic opportunity is to skip those products entirely, converting a dense cubic loop into a band-limited one. This is the same principle behind sparse matrix formats, banded solvers, and compressed storage in numerical computing.

Design blueprint · intersect the two bands

Visualise the band of A as the set of columns reachable from a row, and the band of B as the set of rows that can reach a column. For an output cell (i, j), a product A[i][k] · B[k][j] survives only where both ranges overlap. Clamp the overlap to the real array bounds [0, N-1], then sum.

Therefore C[1][2] = A[1][1]·B[1][2] + A[1][2]·B[2][2] = 4·2 + 5·6 = 38, printed as 0038. A naive loop would have evaluated two guaranteed-zero terms as well.

Algorithm

  1. Read N, p, q, r, s. Validate the input and return quietly on failure.
  2. Read A and B into fixed 20 × 20 arrays. The bounds are part of the contract, so no dynamic allocation is needed.
  3. For each output row i and column j, initialise lo = i - p and hi = i + q.
  4. Intersect with B’s band: lo = max(lo, j - s) and hi = min(hi, j + r). Clamp lo to 0 and hi to N - 1.
  5. Sum A[i][k] * B[k][j] for lo <= k <= hi. If the range is empty, the cell remains zero.
  6. Print the result with the exact separator and padding rules.

Correctness argument

For any k < i - p or k > i + q, the band property of A gives A[i][k] = 0. For any k < j - s or k > j + r, the band property of B gives B[k][j] = 0. Hence every term omitted by the restricted loop is exactly zero, and every term retained lies in the intersection. Clamping removes only indices that do not exist in the arrays. The computed sum therefore equals the full matrix product for every cell (i, j).

Complexity

Time: O(N² + ∑i,j overlap(i,j)). The worst case, when all four bandwidths are N - 1, is O(N³); narrow bands make it much cheaper. Memory: O(N²) for the three matrices. With N <= 20, even the worst case is only about 8,000 multiply-adds in total, far below any practical limit.

Pitfalls

  • Zero-based versus one-based bounds. The rendered formula in the original screenshot may appear to use 1 and N, but the statement declares zero-based indexing. Use 0 and N - 1, as the samples require.
  • Signed padding. %04d counts the sign, so -24 prints as -024, not -0024.
  • Trailing spaces. Print the separator before every element except the first in its row.
  • Overflow. With |entry| <= 99 and N <= 20, the largest magnitude is 20 × 99 × 99 = 196,020, which fits in 32-bit int. If the constraints were larger, a 64-bit accumulator would be required.
  • N = 1. All bandwidths are zero; the single product must still be printed.

Checkpoint questions

  1. Why is it safe to ignore entries of A and B that lie outside their declared bands, even if the input file happens to contain a non-zero value there?
  2. Derive the intersection bounds for a cell on the top edge (i = 0) and explain which terms the clamp removes.
  3. How would the memory usage change if only the band were stored rather than the full matrix?

Problem 02 · Mathematical reductionThe Josephus Problem

A circular elimination process with a simple recurrence hiding underneath it: do not simulate the circle if you can renumber it.

Input
Two integers N K
Output
Survivor’s 1-based number
Core idea
Renumber after each elimination
Cost
O(N) time, O(1) memory

Statement

N people stand in a circle, numbered 1 to N clockwise. Counting starts at person 1. Every K-th person is eliminated, and counting resumes at the next remaining person, again from 1. The process continues until one person remains. Print that person’s number.

The constraints are 1 <= N <= 1000 and 1 <= K <= 1000.

Samples
InputOutputInterpretation
7 34Seven people, every third eliminated
5 23Five people, every second eliminated
10 110Elimination in order; the last person survives

Concept · renumbering as a problem-solving move

After the first elimination, the remaining people still form a circle of the same kind, just smaller. If we renumber them starting from the person where counting resumes, the smaller circle is an independent copy of the original problem with parameter n - 1. The only work left is to translate a position in the smaller numbering back into the original numbering. This is the essence of a recurrence: solve a smaller instance, then undo the relabelling.

Design blueprint · the circle and the shift

  • Eliminated first: person 3
  • Then 6, 2, 7, 5, 1
  • Survivor: person 4

Each elimination restarts the count at the next remaining person. The circle shrinks by one, but the rule never changes.

Deriving the recurrence

Let J(n) be the zero-based position of the survivor among n people when counting starts at position 0. For one person, J(1) = 0. With n people, the first eliminated person is at position (K - 1) mod n. Counting resumes at the next person, so if we relabel that person as position 0, the remaining circle has n - 1 people. By the induction hypothesis, the survivor has position J(n - 1) in the relabelled circle. To recover the original position, add K (the length of the shift) and reduce modulo n:

J(n) = (J(n−1) + K)  mod  n,    J(1) = 0.

The final answer is J(N) + 1 because the problem numbers people from 1.

Relabelling example: remove person 3 from N = 7
New 0-based position012345
Original person456712

A survivor at new position 0 is person 4 in the original circle. Adding K = 3 to the new position and reducing modulo the original size performs exactly this translation.

Algorithm

  1. Read N and K.
  2. Set survivor = 0, the base case for one person.
  3. For i = 2 up to N: survivor = (survivor + K) % i.
  4. Print survivor + 1.
Trace for N = 7, K = 3
Circle size iComputationJ(i)

J(7) = 3 in zero-based indexing, so the printed answer is 4.

Correctness argument · induction

Base case. For n = 1, the only person is at position 0, so J(1) = 0.

Inductive step. Assume the recurrence gives the survivor for n - 1 people. In a circle of n people, the first elimination removes position (K - 1) mod n. Renumber the remaining people from 0 starting at the next survivor candidate. This is a circle of n - 1 people obeying the same rule, so its survivor is at position J(n - 1) in the new numbering. The new position 0 corresponds to original position K mod n; therefore the original position is (J(n - 1) + K) mod n. This is exactly the recurrence.

By induction, the loop computes J(N), and adding one converts the zero-based position to the problem’s one-based person number.

Complexity

Time: O(N) — at most 999 iterations. Memory: O(1). A direct circular-array simulation would take O(NK) time and O(N) memory; at the stated limits that is still feasible, but the recurrence is shorter, allocation-free, and illustrates a reusable mathematical technique.

Pitfalls

  • Confusing 0-based and 1-based positions. Do the recurrence in zero-based indexing, then add one exactly once, at the end.
  • Forgetting the modulo. K may exceed the current circle size, so the shift must always be reduced modulo i.
  • Off-by-one in the base case. Starting from survivor = 0 and looping from i = 2 is correct; starting the loop at i = 1 or initialising to 1 produces the wrong answer.
  • N = 1. The loop body never executes and the answer is 1.
  • K = 0. The constraints exclude it. A modulo by zero would be undefined, so input validation or a documented precondition is appropriate in general-purpose code.

Checkpoint questions

  1. Why does relabelling the circle not change the structure of the problem?
  2. For K = 1, explain both the simulation outcome and why the recurrence produces N.
  3. Explain why J(n) can decrease when n increases. Give an example from the trace table.

Problem 03 · LIFO disciplineBalanced Parentheses

Nesting is a last-in, first-out property. A stack turns that observation into a linear-time decision procedure for strings of round, square, and curly brackets.

Input
One bracket string of length 1–1000
Output
Valid or Invalid
Core idea
Push openers; closers must match the top
Cost
O(L) time and O(L) memory

Statement

A sequence of brackets is balanced when every opening bracket has a corresponding closing bracket of the same type, and every closing bracket closes the most recently opened bracket that is still open. The input is a single non-empty line of length between 1 and 1000 containing only (, ), [, ], {, and }, with no spaces.

Print Valid if the sequence is balanced, otherwise print Invalid. Print nothing else.

Samples
InputOutputWhy
{[()()]}ValidProperly nested groups
{[(])}InvalidA square bracket would have to close over a round one
(([]){})ValidTwo balanced groups side by side

Concept · the stack as a record of unresolved obligations

When an opening bracket is read, it creates an obligation that must be satisfied later. The most recent obligation must be satisfied first, because brackets cannot cross. The stack stores exactly those pending obligations, from oldest at the bottom to newest at the top. A closing bracket is legal only if it discharges the obligation on top; otherwise the nesting is either crossed or unmatched.

Design blueprint · push, match, pop

The stack ends empty, so the sequence is Valid.

Mismatched type: {[(])}

After reading {, [, (, the next character is ]. The top of the stack is (, not [, so the closer cannot be matched. The sequence is Invalid.

Closer without an opener: )(

The first character is already a closer and the stack is empty. No opening obligation exists, so the sequence is Invalid. Counting one of each type would incorrectly accept it.

Algorithm

  1. Read one line with fgets into a buffer of size MAXLEN + 2, enough for 1000 characters, the newline, and the terminator.
  2. Scan characters until '\0', '\n', or '\r'.
  3. For (, [, or {, push the character and increment top.
  4. For a closing bracket, compute the required opener. If the stack is empty or its top differs, set ok = 0 and stop. Otherwise decrement top.
  5. For any other character, set ok = 0 and stop. The input contract excludes such characters, but rejecting them is safer than silently ignoring them.
  6. After the scan, if top != 0, some opener was never closed; set ok = 0.
  7. Print Valid if ok is still 1, otherwise Invalid.

Correctness argument · stack invariant

At every point during the scan, the stack contains exactly the open brackets that have been read but not yet closed, ordered from oldest at the bottom to newest at the top. This is true initially (empty stack) and is preserved by each action: an opener is added at the top, and a legal closer removes the top because the top is precisely the most recent unresolved opener.

If a closer does not match the top, the bracket that must be closed most recently is of a different type, so the sequence cannot be balanced; stopping is correct. If a closer arrives on an empty stack, there is no open obligation for it, so the sequence is unbalanced. At the end, a non-empty stack means at least one opener was never closed. Conversely, if the scan completes with an empty stack and no mismatch, every opener was matched in the correct order, so the sequence is balanced. These cases are exhaustive.

Complexity

Time: O(L), because each character is examined once and each bracket is pushed and popped at most once. Memory: O(L) for the stack, with L <= 1000. The fixed array char stack[1001] is sufficient and avoids dynamic allocation.

Pitfalls

  • Counting is not enough. )( contains one opener and one closer but is invalid; {[(])} has matching counts but crosses types. Only order-aware matching works.
  • Line endings. If the input uses Windows line endings, stop the scan at '\r' as well as '\n'; otherwise the carriage return may be treated as an unexpected character.
  • Buffer size. A 1000-character line needs 1002 bytes including the newline and terminator. A buffer of exactly 1000 would truncate the line.
  • Early termination. Once a mismatch is found, no later character can repair the prefix, so stopping is safe.
  • Unexpected characters. The contract says only brackets appear; nevertheless, treating anything else as invalid prevents silent acceptance of malformed input.

Checkpoint questions

  1. Why can a correctly balanced sequence never require more than L/2 stacked openers?
  2. Modify the algorithm conceptually to report the index of the first offending character. What extra state is needed?
  3. What would change if the input could contain several independent lines?

Problem 04 · Boundary simulationSpiral Matrix Traversal

Peel the matrix like an onion. Four moving boundaries describe the unvisited region, and four sweeps print its outer layer in clockwise order.

Input
N M, then an N × M matrix
Output
All elements in clockwise spiral order
Core idea
Shrink top, right, bottom, left
Cost
O(N·M) time, O(N·M) input storage

Statement

Read an N × M integer matrix. Starting at the top-left corner, move right first and continue inward in a clockwise spiral until every element has been printed exactly once. The constraints are 1 <= N, M <= 30, and every entry is between -1000 and 1000.

Print one line containing all N × M elements separated by a single space, with no trailing space.

Concept · invariants over coordinates

Instead of tracking the current direction and turning at visited cells, maintain the rectangle of cells that have not yet been printed. This invariant is compact, easy to reason about, and independent of the matrix content. Each sweep prints one side of the rectangle and moves that side inward, so the unvisited region remains a rectangle after every step.

Algorithm

  1. Read N and M, then the matrix.
  2. Set top = 0, bottom = N - 1, left = 0, right = M - 1.
  3. While top <= bottom and left <= right:
  4. Print a[top][left..right]; increment top.
  5. Print a[top..bottom][right]; decrement right.
  6. If top <= bottom, print a[bottom][right..left]; decrement bottom.
  7. If left <= right, print a[bottom..top][left]; increment left.
  8. Print a newline after the loop.

Why the two guards are essential

Consider a single remaining row (top == bottom). The top sweep already prints that row from left to right. Without a guard, the bottom sweep would print the same row from right to left, duplicating every element. The symmetric problem occurs for a single remaining column: the right sweep already printed it, and the left sweep would print it again. The conditions top <= bottom and left <= right check whether the layer still has a distinct opposite side before printing it. Tests with N = 1 or M = 1 exist precisely to catch this bug.

Correctness argument · rectangle invariant

At the start of every iteration, the rectangle [top..bottom] × [left..right] is exactly the set of unprinted cells. Initially this is the whole matrix. The four sweeps print its outer layer in clockwise order and then shrink the corresponding boundary, so the remaining unprinted cells form the smaller rectangle for the next iteration. The guards ensure that a sweep is skipped when the layer has collapsed to a single row or column, so no cell is printed twice. Each iteration prints at least one cell and the rectangle strictly shrinks, so the loop terminates. When the rectangle is empty, every cell has been printed exactly once, in the required clockwise order.

Complexity

Time: O(N · M), because each cell is printed exactly once. Memory: O(N · M) for the matrix; the traversal itself uses O(1) additional state. With at most 30 × 30 = 900 cells, a fixed array int a[30][30] is sufficient.

Pitfalls

  • Duplicating the last row or column. This is the classic spiral bug; always guard the third and fourth sweeps.
  • Updating a boundary too early. The right sweep must start one row below the just-printed top row, and the bottom sweep must end one column left of the just-printed right column. The order of the increments matters.
  • Trailing space. A helper that prints a space before every element except the first is safer than trimming afterwards.
  • Negative values. Do not special-case them; %d already prints the minus sign correctly.
  • Non-square matrices. Do not use N for both dimensions. Rectangular cases such as 2×5 and 5×3 expose swapped bounds immediately.

Checkpoint questions

  1. Trace the boundary values for a 1×5 matrix and identify exactly which guard prevents duplicate output.
  2. How would the algorithm change for a counter-clockwise spiral starting at the top-left and moving down first?
  3. Why is the number of loop iterations approximately ceil(min(N, M) / 2)?

Problem 05 · Hierarchy and distanceTree Exploration

Explore a tree level by level, and impose a deterministic order inside each level. Breadth-first search supplies the levels; sorting supplies the tie-break.

Input
N, then N-1 edges {a,b}
Output
Visit order, separated by spaces
Core idea
BFS distances, then sort by (distance, id)
Cost
O(N²) with an adjacency matrix

Statement

You are given a tree with N nodes numbered 1 to N. Starting from node 1, visit the tree according to these rules:

  1. visit node 1 first;
  2. explore all directly connected, unvisited nodes before exploring nodes farther away;
  3. nodes at the same distance from node 1 must be visited in ascending numerical order;
  4. each node must be visited exactly once.

The first line contains N (1 <= N <= 100). Each of the next N - 1 lines contains one edge written exactly as {a,b} with no spaces. Edges are undirected, may appear in any order, and either endpoint may appear first. The input is guaranteed to form a valid tree.

Print one line with the visited node numbers in order, separated by a single space, and print no other text.

Concept · distance is the primary key, identity is the tie-break

Rule 2 is exactly breadth-first search: all nodes at distance d are visited before any node at distance d + 1. Rule 3 adds a second, independent ordering requirement within each level. Separating these two concerns is the key design decision. BFS answers “how far?”; a sort answers “in what order within the same distance?” Trying to satisfy both by cleverly ordering adjacency lists is fragile and, as shown below, incorrect.

Sorting by (distance, node number) produces 1, 4, 2, 6, 3, 5. Notice that node 6 has a larger number than node 3 and lies at a smaller distance, so distance must be the primary key; node 2 and node 6 share a distance, so their numbers decide the order.

Why sorting each adjacency list is not sufficient

Per-parent BFS: wrong

Edges: {1,2}, {1,3}, {2,5}, {3,4}. Level 1 is 2, 3. Node 2 is processed first and enqueues 5; node 3 then enqueues 4. Discovery order within level 2 is therefore 5, then 4.

1 2 3 5 4

Level-global ordering: correct

Both 4 and 5 are at distance 2, so the rule requires ascending numerical order regardless of which parent discovered them first.

1 2 3 4 5

A smaller-numbered parent can have a larger-numbered child. Sorting adjacency lists only orders siblings under the same parent; it cannot order nodes across different parents. The reference solution therefore decouples BFS from the final ordering. Test cases 6 and 10 are designed to expose this exact mistake.

Algorithm

  1. Read N.
  2. For each of the N - 1 edges, parse the format {a,b} with scanf(" { %d , %d }", &a, &b) and set both directions in an adjacency matrix. The leading space in the format skips the newline left by the previous read.
  3. Initialise every distance to -1; set dist[1] = 0 and enqueue node 1.
  4. Run standard BFS: dequeue u, and for each unvisited neighbour v, set dist[v] = dist[u] + 1 and enqueue v.
  5. Collect all nodes with a non-negative distance into an order array.
  6. Insertion-sort the array by the key (dist[v], v) ascending.
  7. Print the nodes separated by single spaces.

Correctness argument

Breadth-first search computes, for every reachable node, the minimum number of edges from the source. In a tree every node is reachable from node 1, so dist[v] is exactly the distance defined in the statement. Sorting by dist therefore places nodes in non-decreasing distance, satisfying rule 2 and the first part of rule 1. The secondary key v orders all nodes that share a distance in ascending numerical order, satisfying rule 3. The order array contains each node exactly once, satisfying rule 4. Hence the printed sequence is precisely the required traversal.

Complexity

Time: BFS over an adjacency matrix is O(N²), and the insertion sort is O(N²) in the worst case, so the total is O(N²). With N <= 100 this is at most about 10,000 basic operations. Memory: O(N²) for the 101 × 101 adjacency matrix plus O(N) for the queue, distances, and order. An adjacency-list representation would reduce the BFS to O(N) and the sort to O(N log N), with O(N) memory.

Pitfalls

  • Parsing the braces. %d alone will not skip a literal {. The format string must contain the braces and the comma, and the leading space lets scanf skip the newline between edges.
  • Printing in discovery order. Discovery order is not necessarily level-sorted across parents. Sort by (distance, id) or collect each level explicitly and sort it.
  • One-based numbering. Node N is valid, so arrays need size N + 1. Off-by-one errors here are common when converting from zero-based array thinking.
  • N = 1. No edge lines follow. The BFS visits node 1 and the output is 1.
  • Unreachable nodes. The input is guaranteed to be a tree, so this cannot occur. A defensive implementation skips nodes whose distance remains -1, as the reference does.
  • Trailing space. Print spaces only between values.

Checkpoint questions

  1. Construct a tree in which two nodes at the same distance are discovered in the opposite order from their numerical order.
  2. Why does a tree require exactly N - 1 edges, and why does that guarantee connectivity in this problem?
  3. How would you output the nodes grouped by level on separate lines without changing the BFS?

VerificationThe test suite

The repository ships 47 executable cases across five suites. Each case is a pair of files: testN.in is fed to standard input, and testN.out is the exact expected standard output. Verification is byte-for-byte.

Running the harness

./run_tests.sh

The script compiles every solution with gcc -std=c11 -Wall -Wextra -O2, builds the binaries in a temporary directory, runs each *.in file, and compares the result with the matching *.out using diff -u. It prints PASS or FAIL for each case, then a final summary, and exits non-zero if anything failed. Override the compiler with CC=clang ./run_tests.sh if desired.

Design blueprint · how a case flows through the harness

  1. Select source and suite. For example, run_suite spiral spiral_matrix_traversal.c tests/spiral.
  2. Compile once. A build failure stops the suite immediately and is reported as BUILD FAILED.
  3. Enumerate inputs. Every tests/<suite>/*.in file becomes one case; the expected file is the same name with .out.
  4. Execute with redirection. The binary reads the input file and writes to a temporary actual-output file.
  5. Compare. diff -u prints the first differing lines; any difference marks the case and the whole run as failed.
  6. Summarise. ALL TESTS PASSED appears only when every suite builds and every case matches.

Reading the suite as a specification

The cases are not arbitrary. Together they encode the boundary conditions that a correct solution must satisfy: minimum sizes, degenerate dimensions, maximum sizes, signed values, reversed input order, and deliberately adversarial orderings. When adding a new case, ask which invariant it probes and whether a plausible wrong solution would fail it. A test that no incorrect program could fail adds confidence but little diagnostic value.

PedagogyA study plan

The five problems are arranged so that each introduces a technique used again later: structured sparsity, mathematical reduction, stack invariants, boundary simulation, and graph traversal. The following plan is a suggestion, not a deadline.

A disciplined debugging protocol

  1. Reproduce the smallest failure. Reduce the input while the program still fails. A three-element case is easier to reason about than a 900-element matrix.
  2. Predict before you print. Write down what each variable should contain after the next iteration. Then compare with reality. This distinguishes a misunderstanding from a typo.
  3. Inspect the invariant. If the stack, boundary, or distance array violates its intended meaning, the bug is usually one line before the symptom.
  4. Enable diagnostics. Compile with -fsanitize=address,undefined to catch out-of-bounds access, signed overflow, and other silent errors:
    gcc -std=c11 -Wall -Wextra -g -fsanitize=address,undefined \ -o /tmp/prog solution.c
  5. Compare against a slow oracle. For small inputs, write a brute force version and compare outputs. Agreement on hundreds of random small cases is strong evidence of correctness.
  6. Remove diagnostics and re-run the exact suite. A fix is not complete until the original failing case and all previous cases pass.

Exercises

Consolidation

  1. Re-implement all five programs from a blank file without consulting the listings. Compare your version with the reference only after it passes the suite.
  2. For each program, write down the loop invariant in one sentence. If you cannot, the code is not yet understood.
  3. Add one boundary test per suite that is not already present, and explain which wrong implementation it would catch.

Extension

  1. Banded matrices: store only the band in a compressed array and recompute the product. Measure the memory saved for N = 20, p = q = 1.
  2. Josephus: implement the circular linked-list simulation and compare its running time with the recurrence for N = K = 1000.
  3. Parentheses: report the index and type of the first error instead of only Invalid. Then extend the program to verify brackets across multiple lines.
  4. Spiral: produce a counter-clockwise spiral, and then a spiral that starts at the centre and expands outward.
  5. Tree: print one line per level, then compute the height and the number of leaves. Finally, replace the adjacency matrix with adjacency lists and preserve the output.

Verification

  1. Write a brute-force oracle for the banded product and compare it with the band-limited version on random small matrices.
  2. Generate random trees, compute the expected order with an independent level-by-level algorithm, and compare.
  3. Fuzz the bracket checker with random strings over the six bracket characters and compare against a recursive-descent parser.

A final recommendation

Keep a short engineering journal. For each problem, record the first design you tried, the first input that failed, the root cause, and the fix. Over five problems this produces a personal catalogue of mistakes that is far more valuable than a folder of finished source files. The goal is not merely to solve these five exercises, but to recognise the same structures in the next fifty.

Glossary

Bandwidth

The maximum distance of a non-zero entry from the main diagonal. Lower and upper bandwidths may differ.

Invariant

A property that is true before and after every loop iteration and, together with termination, establishes the result.

Breadth-first search

A traversal that visits all nodes at distance d before any node at distance d + 1, implemented with a queue.

Oracle

An independent, usually slower, implementation used to check a faster solution on small inputs.

Degenerate case

A boundary input in which a general dimension or structure collapses, such as a 1×1 matrix or a single-node tree.

Byte-for-byte comparison

An exact textual comparison in which whitespace, punctuation, and newlines all matter.
